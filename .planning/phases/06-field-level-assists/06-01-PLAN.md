  <name>Task 1: Create field generation routes</name>
  <files>packages/backend/src/routes/generate-field.ts</files>
  <action>
Create new Hono router with three field generation endpoints:

1. **POST /narrative-hook** - Generate narrative hook text
   - Request schema: `{ nodeType, biome, name, themes, entityTypes, act?, nodeMetadata? }`
   - Uses `streamSSE` from hono/streaming for token-by-token streaming
   - System prompt: Narrative writer for Australian Gold Rush cosmic horror, 1-3 sentences, second person present tense
   - Streams tokens via SSE with `{ type: 'token', content: string }` events
   - Final event: `{ type: 'done', content: fullText }`
   - Error event: `{ type: 'error', error: string }`

2. **POST /beat** - Generate single beat prose
   - Request schema: `{ nodeType, biome, role, context?, narrativeHook?, existingBeats? }`
   - Streams single beat text (50-150 chars)
   - System prompt: Include beat role guidance (setup, escalation, reveal, etc.)

3. **POST /beat-list** - Generate beat outline suggestions (non-streaming)
   - Request schema: `{ nodeType, biome, name, themes, narrativeHook? }`
   - Returns JSON: `{ beats: [{ id, role, text }] }`
   - Uses beat sequence templates from existing patterns (3-5 beats based on node type)
   - Non-streaming because it returns structured data

Import `completeWithRetry` from llm-client.ts. For streaming endpoints, do NOT use `completeWithRetry` directly - instead use a streaming-aware approach:
- Get active provider via `getActiveProvider()`
- Create OpenAI/Anthropic client
- Use streaming API (`stream: true` for OpenAI, or Anthropic streaming)

Reference existing streaming.ts for SSE patterns but simplify - field generation doesn't need job tracking.

Use Zod schemas for request validation with `zValidator('json', schema)`.
