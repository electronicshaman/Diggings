  <action>
Rewrite `streaming.ts` to properly implement SSE with all required features:

**streaming.ts changes:**

1. Remove the old `createSSEStream` and `streamSSE` functions

2. Create new `streamGeneration` function that:
   - Accepts: `c: Context` (Hono context), `request: GenerationRequest`, `jobId: string`
   - Sets SSE headers with anti-buffering:
     ```typescript
     c.header('Content-Type', 'text/event-stream');
     c.header('Cache-Control', 'no-cache, no-store, must-revalidate');
     c.header('Connection', 'keep-alive');
     c.header('X-Accel-Buffering', 'no');  // Prevents nginx buffering
     c.header('X-Content-Type-Options', 'nosniff');
     ```
   - Returns a Response with a ReadableStream

3. Inside the ReadableStream:
   - Implement heartbeat interval (ping every 12 seconds):
     ```typescript
     const heartbeat = setInterval(() => {
       controller.enqueue(encoder.encode(formatSSE('ping', { timestamp: Date.now() })));
     }, 12000);
     ```
   - Clear heartbeat on stream close or error

4. Update `formatSSEMessage` to use proper SSE format:
   ```typescript
   function formatSSE(event: string, data: any): string {
     return `event: ${event}\ndata: ${JSON.stringify(data)}\n\n`;
   }
   ```

5. Event types to send:
   - `ping`: Heartbeat with timestamp
   - `progress`: Stage updates with { jobId, stage, progress, message }
   - `partial`: Partial results (outline after stage 1, content after stage 2)
   - `complete`: Final result with full GenerationProgress
   - `error`: Error with { jobId, error, retryable }

6. Integrate job-tracker:
   - Update job status to 'running' when stream starts
   - Update progress/stage as generation proceeds
   - Update to 'completed' or 'failed' when done

7. Error classification for `retryable` flag:
   - retryable=true: 429 (rate limit), 503 (service unavailable), network errors
   - retryable=false: 400 (bad request), 401 (auth), validation errors

**generate.ts changes:**

1. Import `streamGeneration` from streaming service
2. Import `createJob`, `updateJobStatus`, `getJob` from generation index

3. Update POST /stream endpoint:
   - Create job first with `createJob`
   - Call `streamGeneration(c, request, job.jobId)`
   - Return the stream response

4. Add GET /job/:jobId endpoint:
   - Lookup job by ID using `getJob`
   - Return job status, progress, result/error
   - Used for reconnection: client can poll this to check if job completed while disconnected

5. Ensure the POST /stream endpoint validates request with zValidator as it currently does
